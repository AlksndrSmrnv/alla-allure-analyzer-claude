# Контекст разработки alla-launch

Настройка от 2026-10-03. Цель — проверяемая разработка скилла для Qwen Code.

## Что настроено

`AGENTS.md` отделяет разработку от исполнения `alla-launch`, направляет к общей
карте `CLAUDE.md` и правилам затронутой области. Codex читает `.claude/rules/` явно.
Планы и справочники загружаются по задаче. Правило Context7 в глобальном
`~/.codex/AGENTS.md` сохранено; проектная инструкция поддерживает его.

В локальной конфигурации до изменений уже были `gpt-6.1-sol`, `ultra` и multi-agent.
Проектная `.codex/config.toml` сохраняет `ultra`, включает мультиагентов и задаёт
три параллельных дочерних агента с тем же уровнем reasoning. Модель наследуется.
Это не доказательство улучшения ответа: результат оценивается отдельно.

Codex CLI на этой машине: `0.160.0`. Qwen CLI не найден в PATH. Конфигурация
проекта применяется только для trusted checkout и загружается при новом запуске;
настройки уже открытого чата могут иметь приоритет.
Источники: [конфигурация Codex](https://learn.chatgpt.com/docs/config-file/config-reference),
[обнаружение AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Проверка качества

Команды, синтетические сценарии и отчёт — в [skill-quality.md](skill-quality.md).
Успешный pytest подтверждает Python-поведение и парсеры. Тесты на текст задания
проверяют наличие директив. Ни один из этих результатов не доказывает выбор
скилла или качество диагноза Qwen.

Исходная линия до этой настройки: **806 pytest passed**, ruff прошёл,
mypy — **55 ошибок в 7 файлах**. Эти ошибки уже существовали; новые сравниваются
с исходными. Runtime Qwen не запускался: нет CLI и подтверждённого синтетического
стенда. Сценарии получают `not_run`, а не положительную оценку.

Итог после настройки: **821 pytest passed**, ruff прошёл, строгий mypy новых
файлов прошёл; исходные 55 ошибок mypy не изменились. Harness выполнил **11**
проверок протокола и записал **12** отдельных сценариев Qwen как `not_run`.
Самодостаточность проверена реальным запуском копии скилла без корневого wrapper.
Независимое ревью выявило и подтвердило исправление ошибок агрегации статусов,
описания P03 и полноты controller fingerprint.

Read-only команда `codex debug prompt-input` подтвердила загрузку проектного
`AGENTS.md`, глобального Context7 и доступность локального `skill-evaluation`.
TOML конфигурации разобран без ошибок; текущая сессия не перезапускалась.

Независимый аудит подтвердил два контекстных пробела: смешение runtime-инструкций
с разработкой и предположение об автоматической загрузке `.claude/rules/` в Codex.
Они закрыты проектной маршрутизацией. Возможное ложное срабатывание продуктового
описания на запрос разработки пока не наблюдалось: это гипотеза для отрицательного
runtime-сценария, а не установленный дефект.

### P04: субагенты и встроенная роль Qwen (2026-10-03)

P04 (40 кластеров, 4 пакета субагентов) доходит до `done` со всеми разборами, но субагенты
нарушают правило «в shell только команды скилла»: смотрят папки (`ls`/`find`), читают чужие
пакеты и `state.json`. Исправлено: раздел «Где искать код автотеста» печатается всегда
(`7f77719`) — субагенты перестали искать код теста сами; правила называют запрещённые
команды (`9cf64ef`) — осмотров стало меньше (13–17 → 3–6), исходники скилла больше не читают.
Лог запросов показал причину остатка: Qwen запускает субагента как `general-purpose` с
системной подсказкой «сначала осмотри состояние, ищи широко», и текст prompt пакета
(`69c1dfe`) её не перебивает (5–6 осмотров на прогон). Надёжный путь — собственный
субагент Qwen (`.qwen/agents/`) с узкой ролью и набором инструментов; это меняет установку
скилла, решение за владельцем. Ещё: длинный отчёт (9 тыс. символов) Flash иногда выводит
не дословно, «поправляя» грамматику. Стенд держит проект вне папки результатов: раньше
агент поиском выше проекта читал trace и журнал TestOps стенда.
Итог: свой субагент `alla-batch` (`197202d`) убрал осмотр папок — в проверочном P04 ноль
посторонних shell-команд, все 7 вызовов `agent` ушли в `alla-batch`, токенов втрое меньше
(1,3 млн против 3,6–4 млн), время 6 минут против 8–10. Ошибочный prompt-фикс `69c1dfe`
откачен. Агент сообщил о ещё одном противоречии — отсылке к «Кадрам стека» без такого
раздела в задании; исправлено без платного запуска. Остаётся: длинный отчёт Flash иногда
выводит не дословно (одно слово в обрезанной строке).

### sut-code: что известно о Qwen Code до прогона (2026-10-15)

Разведка по исходникам Qwen Code 0.25.2 (npm-пакет), настоящий Qwen в сеансе разработки
был недоступен (первые прогоны X02–X04 — 2026-10-17, см. ниже):

- `read_file` смотрит только `.qwenignore` (`shouldQwenIgnoreFile`): файлы копии приложения в
  `.alla-sut/` (свой `.gitignore` с `*`) читаются, как и `alla-reports/`.
- `grep_search` — ripgrep без `--no-ignore-vcs` при `respectGitIgnore` (по умолчанию `true`),
  `glob` фильтрует `shouldGitIgnoreFile`: по копии они молча находят пусто. Поэтому поиск —
  действия расширения `search` и `files`, а правило `no_code_search` поиск Qwen там запрещает.
- `run_shell_command`: таймаут по умолчанию 120 с (`SHELL_COMMAND_TIMEOUT_MS`), до 600 с —
  только если модель передаст `timeout`. Скрипты sut-code укладываются в 110 с (`timeout`
  манифеста), первый клон и большая ревизия идут фоновым процессом.

Проверить на стенде первым делом: субагент не пытается `grep_search` по копии (в задании —
запрет и причина), текст после «--» без кавычек и скобок, повтор `check` после замечаний,
основной агент после «да, верно» выполняет `remember --from-extension`, а не пишет
`feedback/NN.md`.

### review: скриншоты проверяющему (2026-10-16)

Headless `qwen` склеивает stdin и позиционный промпт (`${stdin}  ${prompt}`) и прогоняет
весь вход через `handleAtCommand`: каждое `@путь` к файлу внутри рабочей папки (или
`~/.qwen/tmp`) читается `readManyFiles` и добавляется в конец запроса частями
(`Content from <путь>:` и изображение), без вызова инструмента и без учёта
`--max-tool-calls`. Путь вне рабочей папки пропускается, токен обрывается на пробеле,
скобках, `,;!?` и точке перед пробелом. Поэтому `review` кладёт копии скриншотов в рабочую
папку проверяющего и пишет `@pNN-S<k>.png` в разделе проблемы. Проверка на настоящем
`qwen/qwen3.8-flash` (`--openai-logging`, синтетический разбор V01, 30 с, 22 тыс. токенов): в
запросе после текста — `Content from p01-S3.png:`, подсказка про `zoom_image` и часть
`image_url` (JPEG); проверяющий в note сослался на окно «Мы используем cookie» с картинки.
Заметка: в запрос проверяющего попадают и глобальная память Qwen пользователя
(`## Relevant memory`, каталог `~/.qwen/memories/MEMORY.md`) и список скиллов — контекст не
полностью чистый.
