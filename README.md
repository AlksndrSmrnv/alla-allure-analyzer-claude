# alla

**Скилл [Qwen CLI](https://github.com/QwenLM/qwen-code) для разбора упавших прогонов
Allure TestOps.** Называете номер прогона, а скилл отвечает: что сломалось, почему и что с
этим делать.

```text
/alla-launch 12345
```

Скрипт скилла выгружает прогон из TestOps, собирает ошибки и логи и группирует похожие
падения в проблемы. Каждую проблему разбирает модель Qwen CLI, с учётом кода вашего
проекта автотестов и его базы знаний. В итоге вы получаете краткий разбор в терминале,
полный `report.md` и готовые правки автотестов там, где виноват сам тест.

## Что умеет

- 🧩 **Группирует падения в проблемы.** Сотня упавших тестов превращается в несколько
  причин. Повторы (retry), скрытые и muted-результаты в проблемы не попадают, но
  учитываются.
- 🔍 **Разбирает каждую проблему.** Причина с цитатами из логов и сообщений об ошибке,
  категория (автотест, приложение, стенд, данные или «не ясно»), чего не хватает для
  уверенного вывода и что делать.
- 🗂 **Раскладывает проблемы по разделам:** 🔴 требуют вашего внимания, 🟢 агент поправит сам,
  🟡 править вручную, 🔵 стенд и данные.
- 🛠 **Предлагает правки автотестов.** Показывает diff и записывает только после вашего
  «да». Ослабление теста (удалённые проверки, `@Disabled`, новый `sleep`) отклоняется, смена
  ожидаемого значения помечается «Проверьте:». Правку можно откатить.
- 🧠 **Запоминает причины.** Если вы назвали причину или подтвердили разбор, скилл
  сохраняет её в базу знаний проекта `alla-kb/`. В следующих прогонах он узнаёт такую
  проблему и подставляет рецепт. В многомодульном Java/Kotlin-проекте база ведётся по
  модулям.
- 🔁 **Видит повторы.** Отмечает проблемы, которые уже встречались в прошлых разборах.
- 🔗 **Связывает похожие проблемы.** Помечает разные проблемы, у которых, похоже, одна
  причина.
- ⚡ **Справляется с большими прогонами.** От 10 проблем разбор идёт параллельно, на
  субагентах Qwen CLI.
- 🔒 **Только читает TestOps.** Не пишет в TestOps ни комментарии, ни ссылки. Код проекта
  меняется только через `apply`, после вашего согласия.

## Как выглядит результат

```text
## Разбор прогона #12345 — Nightly regression

[####------] 25 тестов: прошло 10, упало 15
15 упавших тестов -> 3 проблемы:
   🔴 требуют вашего внимания .... 1 (7 тестов)
   🟢 агент поправит сам ......... 1 (3 теста)
   🔵 стенд и данные ............. 1 (5 тестов)

### Коротко
Больше всего падений даёт ошибка приложения при создании заказа без адреса. Пять тестов
входа упали из-за недоступного auth-service — начните со стенда.

### 🔴 Требуют вашего внимания (1)

**Проблема 1** · 7 тестов
Заказ не создаётся: POST /orders отвечает 500.
   Агент считает: [ПРИЛОЖЕНИЕ] NullPointerException в OrderService, когда у заказа нет адреса доставки.
   Что делать:    Передать лог order-service команде заказов.

### 🟢 Агент может поправить сам (1)

**Проблема 2** · 3 теста
Тест ждёт код 200, а сервис отвечает 201.
   Агент считает: [АВТОТЕСТ] Контракт API изменился
   Правка:        `src/OrderTest.java:6` — ждёт вашего «да»

### 🔵 Стенд и тестовые данные (1)

**Проблема 3** · 5 тестов
Вход в систему не проходит: auth-service не отвечает.
   Агент считает: [СТЕНД] auth-service на стенде недоступен (connection refused).
   Что делать:    Проверить, что auth-service на стенде запущен.

Полный разбор: report.md
```

В `report.md` лежит всё остальное: полные разборы, цитаты с указанием источника, все шаги,
список тестов и правки в виде БЫЛО/СТАЛО.

## Установка

Что понадобится: Qwen CLI, Python 3.11+, API-токен Allure TestOps и доступ к PyPI (или к
корпоративному зеркалу).

**1. Скопируйте скилл в проект автотестов.** Папку `qwen-skill/alla-launch/` положите в
`<проект>/.qwen/skills/alla-launch/`.

**2. Попросите скилл установиться.** В Qwen CLI, запущенном в корне проекта:

```text
/alla-launch установи
```

Скилл сам создаст себе окружение (1–3 минуты) и файл настроек `.qwen/skills/alla-launch/.env`.

**3. Впишите адрес TestOps и токен** в `.qwen/skills/alla-launch/.env`:

```text
ALLURE_ENDPOINT=https://testops.company.ru
ALLURE_TOKEN=<ваш токен>
```

Токен в чат не пишите: скилл его не спрашивает и файл `.env` не читает.

**4. Всё, можно разбирать прогоны:**

```text
/alla-launch 123456
```

> 💡 Чтобы Qwen CLI не спрашивал подтверждение на каждый шаг, разрешите не весь `python3`,
> а только команду скилла, причём в двух видах: `python3 .qwen/skills/alla-launch/scripts/alla_skill.py`
> и `python3 <абсолютный путь к папке скилла>/scripts/alla_skill.py` (скрипт сам печатает
> следующие команды с абсолютным путём). Запись файлов разрешайте только в папку
> `alla-reports/`. Режим автоматического принятия правок не включайте: с ним модель сможет
> менять код проекта без показа diff.

Если установка не прошла (нет нужного Python, pip не достучался до PyPI), агент покажет, что
поправить. Подробности — в [`references/setup.md`](qwen-skill/alla-launch/references/setup.md).

## Как пользоваться

Всё происходит в чате Qwen CLI, запущенного в корне проекта автотестов:

| Вы пишете | Что происходит |
|---|---|
| `/alla-launch 12345`, ссылку на запуск или «разбери прогон 12345» | Полный разбор прогона и краткий отчёт |
| «да» в ответ на предложенную правку | Правка автотеста записывается в файл |
| «верни правку 2» | Файл возвращается к прежнему виду |
| «в проблеме 3 причина — …, лечится так: …» | Причина и рецепт уходят в базу знаний проекта |
| «да, запомни» | Разбор агента сохраняется в базу знаний как подтверждённый |
| «эта известная проблема тут ни при чём» | Запись базы знаний больше не предлагается для этой ошибки |
| «проверь разбор» | Проверка хода и качества разбора, отчёт в `review/` |

Номер «Проблема N» в отчёте — тот же, что вы называете в чате.

## Команды скрипта

Вызывать их самому не нужно: агент запускает их сам по ходу установки и разбора. Список —
чтобы понимать, что он делает и на что просит разрешение. Все команды выглядят так:
`python3 .qwen/skills/alla-launch/scripts/alla_skill.py <команда>`.

| Команда | Что делает |
|---|---|
| `setup [--python PATH] [-- pip-аргументы]` | Создаёт окружение скилла и `.env` из образца |
| `check` | Проверяет Python, настройки, базу знаний и доступ к TestOps |
| `prepare <ID или ссылка> [--fresh]` | Выгружает прогон и готовит задания. Неоконченный разбор моложе суток продолжает, `--fresh` начинает заново. Разбор старше суток `prepare` не подхватит и начнёт новый — старую папку продолжает `next <папка>` |
| `next [папка] [--workers N \| --serial]` | Следующий шаг разбора. `--workers` — сколько субагентов (1–8), `--serial` — без них |
| `apply N --run DIR [--yes --diff ХЭШ]` | Показывает diff правки автотеста. С `--yes --diff` записывает её |
| `revert N --run DIR` | Отменяет правку, если файл после неё не трогали |
| `remember N --run DIR [--from-analysis]` | Сохраняет причину и рецепт проблемы N в `alla-kb/` из `feedback/NN.md` ([формат](qwen-skill/alla-launch/references/feedback.md)). Без этого файла команда ничего не сохраняет и отвечает `STATUS: fix`. С `--from-analysis` сохраняет подтверждённый разбор агента |
| `reject N <id> --run DIR` | Помечает, что запись базы знаний `<id>` не относится к проблеме N |
| `skip N --run DIR [--reason …]` | Пропускает проблему N |
| `clean [--older-than-days N] [--dry-run]` | Удаляет старые папки разборов (по умолчанию старше 14 дней) |
| `review [папка] [--no-model]` | Проверяет законченный разбор: ход, правила, качество диагнозов |
| `verify N … --run DIR` | Проверяет разборы, ничего не записывая (служебная, для субагентов) |

Первая строка вывода любой команды — `STATUS: …`: по ней модель понимает, что делать дальше. Исключение — `setup`: у него статус печатается последним, после вывода pip.

## Настройки

Задаются в `.env` скилла или переменными окружения (переменные окружения важнее файла).

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `ALLURE_ENDPOINT` | — | Адрес TestOps, без `/api` в конце (обязательно) |
| `ALLURE_TOKEN` | — | API-токен (обязательно) |
| `ALLURE_SSL_VERIFY` | `true` | Проверка TLS-сертификата TestOps. Не выключайте без крайней нужды, см. ниже |
| `ALLURE_CLUSTERING_THRESHOLD` | `0.60` | Насколько похожими должны быть падения одной проблемы. Ниже порог — крупнее проблемы |

**Корпоративный прокси с собственным сертификатом.** Проверку TLS отключать не нужно:
укажите файл с корпоративным корневым сертификатом в переменной окружения `SSL_CERT_FILE`
(в `.env` скилла она не читается). Этот файл заменяет встроенный список доверенных
сертификатов, поэтому в нём должны быть все нужные корневые сертификаты. `ALLURE_SSL_VERIFY=false`
— только временный обход: он отключает проверку полностью, и API-токен уйдёт любому, кто
перехватит соединение.

Полный список настроек — в [`setup.md`](qwen-skill/alla-launch/references/setup.md#настройки).

## Ограничения

- Прогон задаётся только номером или ссылкой: по имени запуска скилл не ищет.
- Ошибки и логи прогона уходят модели, с которой работает Qwen CLI, как есть, без
  маскирования секретов.
- Код проекта может отличаться от той ревизии, на которой шёл прогон.
- Тесты скилл сам не запускает: проверить исправленный тест нужно вам.
