# Задания, разборы и отчёт

Подробности — в файлах подобластей: `skill-analysis-task.md` (задание кластера), `skill-analysis-images.md` (скриншоты), `skill-analysis-format.md` (цитаты и разбор модели), `skill-analysis-report.md` (отчёт, краткий разбор, сводка), `skill-analysis-confirmed.md` (подтверждённый вывод), `skill-analysis-known.md` (известные проблемы), `skill-analysis-related.md` (похожие проблемы).

`problem_state.current_state` — общий источник диагнозов, признака принятия,
подтверждений, известных проблем и действующих связей для `next`/отчёта и публичного
снимка (`extension_data.py`). Он применяет настоящую проверку разбора и related,
а не парсит report.md. Подтверждения — одна функция `problem_state.confirmations`
(вывод расширения, затем успешно сохранённое исправление инженера, `source = "feedback"`):
её результат `current.confirmed` получают отчёт, сводка, связи, вопрос после отчёта,
снимок и данные `after_report`, поэтому категорию и причину они выбирают одинаково
(подтверждение сильнее анализа). Признак принятия тот же, что в снимке.
Файл обратной связи сам по себе — только вход remember. Успешное сохранение оставляет
`state.accepted_feedback[file_id]` с хешем точного текста и смысловых полей записи базы
знаний; только действующая отметка даёт подтверждённый диагноз из feedback.
Несохранённая или изменённая обратная связь — `feedback_unconfirmed = true`, она не принята.
После успешного сохранения из другого источника точная старая версия feedback игнорируется
(`state.ignored_feedback`), а её последующее изменение снова требует remember.
Узнавание записи базы знаний не имеет отдельного правила только для снимка.
Разбор, ранее записанный скриптом по базе знаний, до next пересчитывается в памяти через
`known_issues.current_auto_text`: та же проверка используется при записи в sync_known_auto.
Изменённая или удалённая запись не оставляет в снимке старый принятый диагноз; ручные
правки анализа сохраняются, чтение снимка не меняет файлы.
В next проверка и выдача заданий разбора предшествуют сборке известных проблем и связей:
`current_state` вызывается после цикла разборов с уже проверенными `analyses`/`flagged`,
посреди незавершённого разбора эти данные по всему запуску не вычисляются.
Все участники тестов экспортируются без лимита старого problem-контекста (20).
Для tickets исходный снимок отделён от проекции конкретной версии; изменение посторонней
проблемы не отменяет её само по себе. Подробности — skill-extensions-tickets.md.
Принятые группы related также сохраняют собственный отпечаток диагнозов и актуальных
подсказок базы знаний (`state.related_scopes`). Снимок может использовать неизменённую
группу при изменении глобального задания других групп. Подтверждённые расширением,
неоднородные, отвергнутые и уже известные проблемы из этого основания исключены;
новое принятое решение related заменяет прежний набор отпечатков. Нет кандидатов —
связи не восстанавливаются, next удаляет вместе related_scopes, related_data_hash и related.
