# Задания: цитаты и разбор модели

- Цитаты идут в «НАБЛЮДЕНИЯ» (`_OBSERVATIONS_NOTE`): id куска (из заголовка) и строка
  именно из него, одной строкой; первой — та, на которой держится причина (при логе — из
  лога, при записи базы знаний — совпавшая с признаком). Цитировать можно только куски с
  заголовком `--- [S… · …] ---`: кадры стека, шаг, база знаний, список тестов и пометки
  отбора — нет (трейс в данных обрезан, кадр из «Кадров стека» в S2 может отсутствовать).
  «ЧТО СЛОМАЛОСЬ» описывает отказ словами; «чего не хватает» — только в «НЕ ХВАТАЕТ».
  «приложение» и «данные» — когда сбой сервиса однозначно показывает цитата: строка лога
  операции теста или текст ошибки самого сервиса в сообщении, трейсе или HTTP-ответе
  (исключение сервиса, ответ валидации, «не найдено»), — или ссылка `БАЗА ЗНАНИЙ:` на точную
  запись той же категории; голый код ответа, расхождение ожидаемого и полученного и скриншот
  этого не показывают — «неизвестно». Директива — `_CONFIRMED_CATEGORY_NOTE` в строке ПРИЧИНА
  каждого варианта (про базу знаний — только при записях). Скрипт
  (`analysis_format.category_errors`, `quotes_checked_source`, `exact_kb` из `entry["kb"]` с
  `origin == "exact"`) отклоняет (`fix`, `CATEGORY_UNCONFIRMED_ERROR`) только разбор, где все
  цитаты — со скриншота (их он не сверяет): однозначна ли сверенная цитата, решает модель по
  заданию. Раньше требовалась цитата из лога (ревью: категорию ставили по правдоподобной
  версии), но в проектах без логов это запрещало выводы даже по исключению сервиса в теле
  ответа (решение пользователя); защита от голого 500 теперь только в тексте задания —
  стенд N01. Потерянный реестр (`sources is None`) проверку не включает. Код 500 и другие 5xx
  без текста ошибки сервиса — «неизвестно», 502/503/504 — «окружение»: сервис недоступен или
  не ответил (E09: 503 «приложением» расходился с эталоном). Кто отдал ответ — сервис или
  прокси — по коду не видно, задание запрещает это утверждать (503 отдаёт и сам сервер, RFC
  9110). Лог сервиса (и балансировщика) — в «НЕ ХВАТАЕТ», только если без него причину не
  подтвердить. «НЕ ХВАТАЕТ» (`_MISSING_NOTE`) — каких данных нет и какая проверка различит
  версии; при «неизвестно» обязателен.
- Цитата причины и детали первого шага из лога нужны лишь при подтверждённой ошибке. Только
  INFO без симптома и без подтверждённой причины в точной записи базы знаний — «неизвестно».

## Разбор модели (`analysis_format`)

Прощающий парсер разделов ЧТО СЛОМАЛОСЬ / ПРИЧИНА / НАБЛЮДЕНИЯ / НЕ ХВАТАЕТ / КАК ИСПРАВИТЬ /
КОД:

- Формат один (`EXPECTED_FORMAT`): наблюдения обязательны, кроме категории «неизвестно», а
  при ней обязателен содержательный «НЕ ХВАТАЕТ». Без наблюдений проверяются только разборы
  `auto`-кластеров — их пишет код (нет данных, сбой подготовки): `sources.observed`,
  `validate_analysis(observed=…)`.
- Наблюдение — `- [S3] «цитата»` (маркер, скобки, жирный и вид кавычек прощаются). Граница
  цитаты — внешняя пара кавычек (`_closing_quote`): у « » и “ ” учитывается вложенность, у
  одинаковых " ' ` — чётность внутренних (апостроф внутри слова — `can't` — и экранированная
  `\"` не считаются); закрывающая стоит перед концом строки или
  пояснением (« — …», « (…)»). Поэтому `«key "id" — missing»` и
  `«…» (поле «customer»)` разбираются верно. Строки «нет»/«-» в разделе — «наблюдений нет» (так пишут при
  «неизвестно»), а не ошибка формата. Цитата ищется **в названном** куске реестра: регистр, пробелы и
  вид кавычек не важны, `…`/`...` делит её на части, идущие по порядку, края частей без
  `.,;:`; минимум 8 букв и цифр. Найдена только в другом куске — ошибка «есть в S2, а не в
  S3 — укажи [S2]». Реестр не найден или повреждён (`load_registry` проверяет
  форму) — это неполадка скилла, а не разбора: модель её не исправит, поэтому разбор
  принимается без сверки цитат (`ClusterAnalysis.sources_lost`). Отчёт показывает такие
  цитаты с пометкой `SOURCES_LOST_NOTE`, в «Замечаниях» — номера проблем, `review` — причина
  `sources_lost`. Раньше это была ошибка `fix`, и модель тратила попытки до «формат нарушен». Совпадение
  цитаты подтверждает наблюдение, а не причинную связь.
- Одна проверка для `next`, `verify` и `remember --from-analysis`:
  `sources.check_entry_analysis` (прикрепляет реестр к разбору — для отчёта). Готовые
  разборы кода (`no_evidence`, `failed_prepare`, `skipped`) содержат «НЕ ХВАТАЕТ».

- последняя строка файла — `ПРИМЕЧАНИЕ: …` (`ANALYSIS_NOTE`, раздел `note`, содержимое
  игнорируется, проверка её не требует): Qwen Code перед `write_file` показывает текст файла
  и вопрос «Применить это изменение?», и без строки коллеги принимали запись отчёта за правку
  файла из `КОД`. Она закрывает предыдущий раздел, поэтому в `КОД`/`БАЗА ЗНАНИЙ`/шаги не
  попадает; есть в `EXPECTED_FORMAT`, шаблоне и примерах `analysis-ok` справочника, в задании
  кластера (`test_every_variant_ends_the_answer_with_the_closing_note`);
- принимает `1.`-нумерацию и «—» после заголовка; каждый заголовок — один раз;
- пункт списка `- Код: …` внутри шагов — текст, а не раздел;
- категория — первое слово из пяти, без «или»/«/»;
- файл и номер строки в КОД проверяются; имя файла без пути принимается, если оно
  однозначно; пути с пробелами — в кавычках/backticks либо существующий начальный путь,
  затем прежний поиск ссылки среди текста; принадлежность проекту проверяется после
  окончательного разрешения файла;
- `БАЗА ЗНАНИЙ: <id>` — только id из предложенных записей, любая фраза = «нет»;
- `parse_summary` показывает модели, что распознано.
