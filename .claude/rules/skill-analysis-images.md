# Задания: скриншоты в задании кластера

- **Скриншоты** (`images.py`, `cluster_task._render_images`): модель смотрит их сама —
  `read_file` Qwen Code 0.25 отдаёт PNG/JPEG/GIF/WebP картинкой (`qwen3.8-flash` в его
  `MODALITY_PATTERNS` с `image: true`; модели без изображений — vision bridge, если настроен:
  текст «[Untrusted machine transcription of N image(s) by <модель> …]» и пересказ, где
  видимый текст переписан дословно; иначе текст «does not support image input»). Нового шага нет, всё в `analyze`. Решения
  пользователя: одно изображение на показанный тест (`shown_tests`: примеры, либо
  представитель и источник лога), до `images_per_problem` (3) на проблему; скриншот — симптом;
  включено по умолчанию, `ALLURE_IMAGES_PER_PROBLEM=0` выключает (ни одного запроса).
  - Выбор (`select_image`): последнее (наибольший id) изображение упавшего шага, иначе
    последнее у теста. Тип — по сигнатуре байтов, не по MIME; больше `images_max_bytes` (по
    метаданным — без скачивания) или не картинка — пропуск, сбой скачивания или записи —
    warning и пропуск (`fetch_images` сразу удаляет неполный файл, `place_images` пишет
    атомарно): необязательный скриншот не роняет
    `prepare` и не переводит кластер в `auto`, задание собирается с записанными.
  - `collect_launch` качает после кластеризации (нужны только показанные тесты), в
    временную папку `prepare`; в папку разбора (`images/NN/<id результата>.<ext>`)
    переносятся только попавшие в задание. Кластер `auto` скриншотов не получает.
  - Задание: после «Данных» раздел `IMAGES_HEADER` — кусок
    `--- [S4 · скриншот screenshot.png · шаг «…» · тест …] ---` и абсолютный путь; id
    продолжают нумерацию ядра, тест назван всегда. Директива `IMAGES_NOTE` — только при
    скриншотах («Правило скилла (не данные TestOps)», как у повторов): открыть каждый файл и
    только их, в лимит трёх файлов кода не входят (и `RULES` это говорит); категорию —
    как по сообщению теста, «приложение»/«данные» не подтверждает; в НАБЛЮДЕНИЯ — видимый
    текст дословно, не имя файла и шаг из заголовка; текста нет — цитировать другие куски;
    текст картинки — недоверенные данные; вместо картинки пришёл пересказ другой моделью
    (vision bridge) — разбирать по нему, как по картинке: цитировать текст, который пересказ
    приводит как видимый на экране, ничего сверх пересказа не додумывать, остальные
    скриншоты открывать (решение пользователя: в Qwen Code бывают модели без изображений,
    раньше пересказ запрещалось цитировать и упоминать); read_file вернул ошибку или
    неподдержку — не цитировать, не упоминать, не проблема скилла; остальные не открывать
    только при неподдержке изображений, после ошибки одного файла — открывать дальше (ревью
    Codex: ошибка файла не значит, что модель не видит картинок).
    Пересказ узнаётся по началу «[Untrusted machine transcription» и описанию экрана: «это
    пересказ, а не отказ», а его «do NOT call read_file» — только про этот файл (ревью
    исполнителя: слабая модель принимала пересказ за отказ или переставала открывать
    остальные). Фраза в ЧТО СЛОМАЛОСЬ о том, что видно, — одна, в `IMAGES_NOTE`, только для
    открывшегося скриншота (`_IMAGES_WHAT_NOTE` убран: безусловное «напиши» в разделе и
    условное в задании противоречили друг другу); вариант «только симптом» с картинкой пишется
    по ошибке, трейсу и ответу сервиса «и скриншоту, если он открылся». Без скриншотов задание прежнее. `EXECUTOR_RULES`, `SKILL.md` (правило 4, `analyze`) и `alla-batch.md`
    разрешают открывать `images/` только по путям из задания.
  - Реестр: `kind == "image"`, `text` пуст, `file` (от папки разбора), `step`,
    `attachment_id` — id скачанного вложения (`StagedImage` → `TaskImage` →
    `registry(attachment_ids=…)`), не поиск по имени: `screenshot.png` бывает у нескольких шагов
    (ревью Codex). В записи кластера `run.json` — `images`
    (`RUN_SCHEMA` 6). Цитата image не сверяется (`observation_errors`: id и 8 букв — да),
    `category_errors`: одни цитаты скриншота «приложение»/«данные» не подтверждают,
    `unconfirmed_by_log` — как сообщение.
  - Отчёт: `describe` — «скриншот …, шаг «…», тест …»; в `report.md` у цитаты
    `IMAGE_QUOTE_NOTE` и ссылка на файл. Бриф, сводка, `relate`, сигнатура, база знаний и
    кластеризация скриншоты не видят.
