# Расширения скилла (`extensions.py`, `extensions/`)

Подробности — в файлах подобластей: `skill-extensions-git-publish.md`, `skill-extensions-sut-code.md`, `skill-extensions-tickets.md`.

Зачем: команды добавляют свои функции (git, задачи, чат) без форка скилла; включение —
одной командой. Руководство автора — `extensions/README.md` (контракт целиком), инструкция
агенту-автору — `extensions/AUTHORING.md` (порядок, неочевидные ограничения из кода, проверка;
меняя поведение `extensions.py` или `session_rules.WRITABLE_RE`, сверь её), для
пользователя — `references/setup.md`, «Расширения»; для модели — `SKILL.md`, «7. Расширения».

## Устройство

- Расширение — папка с `extension.toml`: встроенные `<скилл>/extensions/<имя>/` (выключены),
  свои `<проект>/alla-extensions/<имя>/`; своё с тем же именем заменяет встроенное
  (`overrides_bundled`). Включение — `enabled = [...]` в `<проект>/alla-extensions/config.toml`
  (общее для команды, в git; таблица `[update]` в нём — не расширение, а адрес репозитория для
  `alla_skill.py update`, `skill-protocol-setup.md`); `enable`/`disable` переписывают только эту строку и только в корне
  (до первой таблицы: в `[<имя>]` может быть своя настройка `enabled`); многострочный
  список — отказ; новый текст перед записью разбирается `tomllib` и должен отличаться только
  корневым `enabled`, иначе файл не пишется (`_check_rewrite`), настройки `[<имя>]` переопределяют `[settings]` манифеста того же типа,
  неизвестный ключ — ошибка.
- Контракт `api = 1`. Скилл не импортирует код расширения: скрипты — отдельный процесс
  `sys.executable`, cwd — корень проекта, данные — JSON-контекст (`ALLA_CONTEXT`). Поля
  контекста и переменные шаблона задания — в `extensions/README.md`; их меняют только вместе
  с ним, несовместимо — только с новым `api`.
- События: `after_apply` (`_apply`, только `result.changed`), `after_revert` (`_revert`,
  отметка читается до отката), `after_report` (`next_step` при `done`, один раз на хэш
  `report.md` для каждого расширения: `state.json["extension_reports"]`). Там же, один раз на
  отчёт и набор ошибок (`state.json["extension_problems"]`), — строки о неисправных включённых
  расширениях: сломанное исключено из активных, и его хук иначе молча не сработал бы.
  Отметки пишутся и при пустом выводе хуков: молчаливый хук отчёта тоже не повторяется. Повтор —
  `extensions run <имя> [N]`: `after_apply` только для правки в состоянии `applied`.
- `on_request` (`REQUEST_EVENT`) — функция по просьбе пользователя: если у расширения есть
  этот хук, `extensions run <имя> N [N…] --run DIR [--param k=v…]` (`cli._extensions_request`)
  стреляет им по разу на каждую названную проблему (дубли номеров убираются, номер обязателен,
  правка и `done` не нужны), `confirm` не спрашивается. Без хука `run` — прежний повтор, а
  `--param` и несколько N — ошибка. `parse_params`: ключ `[a-z][a-z0-9_]*`, значение — одна
  строка до 500 символов; в контексте `params` — ключ → список значений, в шаблоне
  `$param_<ключ>` через запятую.
- Контекст проблемы (`problem_context(paths, entry, record, run)`) несёт `tests` (до 20,
  представитель первым) и `sources` — куски «Данных» из реестра `evidence/NN.sources.json`
  (до `MAX_SOURCES_CHARS`); общий контекст — `launch_created` из `run.json` и `params`.
- Хук `task` — задание субагенту `alla-<имя>` (файл агента расширения, проверяется как
  `alla-batch`): контекст `<папка разбора>/extensions/<имя>/<stem>.json`, задание `<stem>.md`,
  в ответ команды — блок «Расширения:» (`ext.block`) с вызовом `agent` и запасным путём без
  `subagent_type`; `confirm = true` — сначала вопрос пользователю. Хук `script` — скилл
  запускает сам, вывод (≤ `OUTPUT_LIMIT`) — пользователю.
- **Время скриптов** — под лимит Qwen на команду shell (120 с): скрипты хуков одной команды
  скилла делят `HOOK_BUDGET_S` (60 с; `fire(deadline=…)`, `hook_deadline()`; `on_request` по
  нескольким проблемам — один срок на все), каждому `min(timeout манифеста, остаток)`, без
  остатка — «не запущено»; действие — не дольше `ACTION_LIMIT_S` (110 с). Проверка манифеста
  (1–600) прежняя. Отметка `extension_reports` пишется **до** запуска хуков `after_report`.
  Причина: при `timeout` 120 зависший хук отчёта убивал `next` до отметки, и каждый следующий
  `next` запускал его снова — отчёт не выводился никогда.
- Действие — `extensions action <имя> <действие> [--context FILE | --run DIR] [-- аргументы]`:
  только включённое расширение; при --context файл только из
  `<папка отчётов>/<разбор>/extensions/<имя>/*.json`. --run строит свежий контекст по папке
  разбора. Без обоих нужен явный --reports-dir; скилл собирает общий контекст без run_dir.
  Первая строка вывода скрипта
  `STATUS: ok|error`, иначе `error`.
- Ошибка расширения (битый манифест, нечитаемый файл агента, упавший или зависший скрипт,
  неверные настройки) — строка блока «Расширения:», статус команды скилла не меняется:
  `discover` ловит `OSError`/`ValueError` манифеста, `active` — любой сбой обхода папок (его
  зовут `prepare`, `next`, `apply`), `fire` — сбой хука. `apply` после записи файла обязан
  ответить `applied`.
- Неисправная своя замена встроенного расширения выключает его: встроенное вместо неё не
  запускается (у команды могли быть свои ограничения — remote, `confirm`). В
  `alla-extensions/` расширение — любая папка (кроме `.`/`_`), без `extension.toml` — тоже
  неисправная: удалённый манифест не возвращает встроенное.
- Хук `task` — не больше одного на событие: задание пишется в `<событие>-NN.md`, второе
  затёрло бы первое. Хуков `script` на событие может быть несколько.
- Агенты включённых расширений ставит `enable` (явная просьба) и `install-files --yes`
  (обновить после `update`; `prepare` в `.qwen/` не пишет, `qwen_files.install_extension_agent`); `disable` убирает файл, только если он совпадает с
  нашим.
- Слэш-команды расширения — `commands = ["commands/<имя>.md"]` в манифесте
  (`_commands`/`_check_command`: `.md`, имя по `NAME_RE`, `description`,
  `disable-model-invocation: true`, не пустой текст). Имена команд скилла заняты
  (`skill_command_names` — из папки рядом с модулем, не из `ws.SKILL_DIR`), одна команда у двух
  включённых расширений — второе в `Active.problems`. Ставятся тем же путём, что агенты:
  `enable`/`install-files --yes` → `.qwen/commands/alla/<имя>.md`, `disable` — убрать, если файл наш.
  Цикл по командам в `_extensions_toggle` — своей переменной (`command`): `name` там — имя
  расширения, по нему подсказка называет таблицу настроек `[<имя>]`.
  `enable` поверх занятой команды отказывает (`command_conflict`) до записи `config.toml` и
  файлов: включённое ставится последним, `active` отдаёт команду первому, и второе затёрло бы
  чужой файл, оставшись неактивным (ревью Codex).
- Модель работу расширения не делает: субагент запускает только команду скилла из задания
  (правило «из shell только команды скилла» не ослаблено). `session_rules.WRITABLE_RE`
  разрешает субагенту только `extensions/<имя>/*.txt` (сообщение коммита).
- Имя `batch` занято (`RESERVED_NAMES`): субагент `alla-batch` расширения затёр бы
  субагента пакетов.

## Новое событие или поле

Вызов `ext.fire` в команде, поля — в `extensions/README.md`, событие — в `EVENTS`, тест в
`test_skill_extensions.py`; если модель должна что-то сделать иначе — `SKILL.md` раздел 7 и
`references/protocol.md`.
