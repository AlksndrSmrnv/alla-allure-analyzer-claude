# Предложения правок автотестов (`proposals`, `apply`, `revert`)

## Когда и что предлагается

- Статус `propose` — для кластеров «тест» с `КОД:`, до 5 на прогон. Лишние и отброшенные
  после 3 попыток видны в отчёте у самой проблемы («Почему агент не правил сам»).
- Формат БЫЛО/СТАЛО. Одно предложение — одна правка: один `ФАЙЛ` и один блок БЫЛО/СТАЛО.
  Повторный заголовок (`Proposal.repeated`) — ошибка «больше одной правки», а не склейка
  блоков. Места рядом агент объединяет в один блок; несколько файлов — «не трогать» с местами
  в «ПОЧЕМУ». Ограничение описано в `proposal-format.md`, `PROPOSAL_RULES`, `SKILL.md` и
  `protocol.md`; его охраняет `tests/test_skill_docs.py`.

## Проверка правки

- Явное ослабление теста отклоняется: удалены/закомментированы вызовы проверок,
  отключение/`@Retry`, пустой catch, новый sleep. Комментарии режутся с учётом строк: `#id` и
  `http://` в кавычках — не комментарий.
- Смена ожидаемого значения и рост таймаута (с единицами измерения и по «владельцу»
  ожидания — вызову или ключу) — не отказ, а «Проверь:» рядом с diff.
- Место правки одно (`_locate`): ближайший к указанной строке (±20) из ещё не исправленных
  БЫЛО и уже стоящих СТАЛО. Если ближайшее — СТАЛО, соседнее БЫЛО не трогается. БЫЛО внутри
  СТАЛО и СТАЛО внутри БЫЛО не считаются.

## Какие файлы можно править

- Только `SOURCE_EXTENSIONS` вне dot-папок и вне
  `DENIED_DIRS = SKIP_DIRS | {"alla-kb", "buildSrc", "build-logic"}` (только в proposals;
  индекс проекта и обход базы знаний не меняются).
- Запрещены известные имена сборки/конфигурации, включая `*.gradle.kts`, `setup.py`,
  `noxfile.py`, `conanfile.py`, `Jenkinsfile.groovy`, gulp/Grunt и конфиги тестовых/JS
  инструментов. Каталог `build`/`out` запрещён в любой части пути, как при индексации.
- Файл не в UTF-8 скилл не трогает.
- Resolver отделён от проверки новых правок: старые применения теперь запрещённых файлов
  сохраняют состояние и защищённый откат. Старое неприменённое предложение для такого файла
  при `next` получает `fix` с требованием «РЕШЕНИЕ: не трогать», места и изменения — в
  «ПОЧЕМУ». Историческое исключение требует совпадающей записи apply; одно найденное СТАЛО
  запреты не обходит.

## `apply`

- Без `--yes` печатает diff и его хэш (пишет `proposals/NN.patch`). С `--yes --diff ХЭШ`
  записывает ровно показанный diff: бэкап `NN.orig`, атомарная запись, окончания строк и BOM
  сохраняются.
- `NN.applied.json` хранит хэши файла до/после, строку и файл.
- В `done` команда apply предлагается только для `not_applied`, включая обычные исходники.

## Состояние применения (`applied_state`: applied | not_applied | unknown)

- По записи: хэш файла == `sha_after` — применено, == `sha_before` — нет.
- Если файл менялся, «не применено» по содержимому **не выводится никогда**: близость к
  исходной версии откат не доказывает, чужая правка может вернуть часть удалённого.
- «Применено» при изменённом файле — только при строгом доказательстве (`_untouched`): общий
  префикс версий «после apply» и текущей покрывает строки СТАЛО либо общий суффикс (все
  отличия по одну сторону), и при этом версия «до apply» этому же условию не удовлетворяет —
  иначе оно ничего не доказывает (так у правки-удаления). Обе версии восстанавливаются из
  `NN.orig`.
- Всё остальное — `unknown`: ручной откат вместе с другими правками, изменённая строка
  правки, недоступная или повреждённая копия с СТАЛО не на записанной строке. Тогда
  `apply` отказывается («не удалось определить»); повтор — только по явному `--repeat`
  (агент — лишь по прямой просьбе пользователя; прежняя `NN.orig` уходит в `NN.orig.1`,
  `.2`…, ничего не затирается). `next` не заставляет модель переписывать предложение, отчёт
  объясняет состояние у самой проблемы.
- Без записи (`revert`, ручное применение) «применено» определяется по СТАЛО, ближайшему к
  указанной строке (`_locate`).

## `revert`

Берёт файл из записи применения (не из предложения) и возвращает бэкап, только если файл не
менялся после `apply` и сам бэкап совпадает с `sha_before` из записи. Повреждённая или
подменённая `NN.orig` — отказ, файл и запись не трогаются. Отметка без любого из полей
`proposal`, `file`, `line`, `sha_before`, `sha_after`, `backup` (`_load_record`) — не отметка:
`applied_state` её не учитывает, `revert` отвечает «отметка повреждена».

## Неоднородная группа

Разбор с «СОГЛАСОВАННОСТЬ: разные проблемы — …» в кандидаты на `propose` не попадает даже с
категорией «тест» и `КОД` (`cli.MIXED_GROUP_NOT_PROPOSED`): одна общая правка для группы с
разными проблемами не предлагается.

## Отвергнутая запись базы знаний

Разбор, опиравшийся на запись, которую потом отвергли (`reject`, `known_issues.rejected`),
лечит неподтверждённую причину. `next` проверяет это до шага `propose` (`_withdrawn_fix`):
правку не просит, а неприменённую снимает из предложений (`cli.REJECTED_NOT_PROPOSED`,
проблема уходит в «править вручную»). `apply` отказывает (`STATUS: error`) при любом
состоянии, кроме `applied`, — и с `--repeat` при `unknown`. Уже применённая правка остаётся в
отчёте и откатывается `revert`.
