# Проверка alla-launch

Проверяй поведение агента отдельно от Python-протокола. Тесты скрипта и наличие нужных слов в
инструкциях не доказывают, что агент правильно выбрал скилл, прочитал данные и завершил разбор.

Пути `qwen-skill/...` ниже и в справочниках указаны от корня этого репозитория.

## Выбор проверки

1. Определи изменённое поведение в `qwen-skill/alla-launch/SKILL.md`, `references/` или
   `scripts/`. Выбери затронутые сценарии из [alla-cases.md](references/alla-cases.md), включая
   хотя бы один запрос, на котором скилл не должен активироваться.
2. Переиспользуй подходящие тесты из `qwen-skill/alla-launch/tests/`. Общие фикстуры находятся
   в `skill_fixtures.py`, синтетический TestOps — в `skill_fake_testops.py`.
   Воспроизводимый локальный запуск и отчёт: `scripts/skill_quality.py`; команды и
   ограничения описаны в `docs/skill-quality.md`.
   Запусти проверки, относящиеся к изменению, в имеющемся окружении проекта; не добавляй тесты
   только на совпадение формулировок.
3. Если доступна безопасная среда Qwen Code, проведи выбранные сценарии на реальном агенте.
   Условия запуска и оценка trace — в [trace-review.md](references/trace-review.md).
4. Сравни результат с прежней версией на одинаковых сценариях, fixtures и настройках.
   Исправляй выявленное поведение узко, затем повторяй затронутые проверки.

## Условия runtime-проверки

Перед запуском проверь наличие и версию Qwen Code доступными read-only средствами, затем
локальную справку. Перед использованием CLI получи актуальные документы через Context7;
если нужные документы недоступны — через официальный источник. Проверяй поддержку каждого флага
у установленной версии. Не придумывай headless-команду или формат trace.

Стенд — `qwen-skill/alla-launch/tests/qwen_stand.py` (команды и границы — в
`docs/skill-quality.md`, раздел «Стенд Qwen»): фейковый TestOps по HTTP на 127.0.0.1,
синтетический проект с копией скилла, отдельный HOME без личных настроек, песочница на запись,
trace и автоматическая проверка объективной части рубрики. Сценарии, которых в стенде нет,
добавляй туда же, а не запускай вручную. Подмена HTTP-клиента внутри pytest не
распространяется на отдельный CLI-процесс. Если Qwen или модели нет, заверши локальные
проверки и отметь сценарии `not_run` с причиной.

Статус стенда `inconclusive` с пунктами «оценить» значит, что автоматические проверки прошли,
а оси вроде Evidence ждут твоей оценки по trace и папке разбора. Одна попытка на быстрой
модели — не вывод: чувствительные сценарии повторяй (`--repeat`).

## Результат

Сохрани запросы, версию скилла, условия запуска, trace и созданные артефакты там, где это
уместно для текущей задачи. Для каждого сценария укажи `pass`, `fail`, `inconclusive` или
`not_run`, оценки по рубрике и ссылку на наблюдаемое доказательство. Отдельно перечисли pytest
проверки: они не заменяют runtime-сценарии. Не называй проверку успешной по одному лишь
валидному Markdown или красивому финальному ответу.
