# Расширения alla-launch

Расширение добавляет скиллу свою функцию — выгрузить правку в git, завести задачу,
отправить отчёт в чат — без форка и без правки кода скилла. Это папка с манифестом:
скилл находит её, по событию разбора запускает субагента или скрипт расширения и передаёт
им данные. Включается и выключается одной командой.

Пример в комплекте — [`git-publish/`](git-publish/): после применённой правки субагент
пишет сообщение коммита, а скрипт выгружает правку в новую ветку.

Пишете расширение с помощью агента — дайте ему [AUTHORING.md](AUTHORING.md): порядок работы,
неочевидные ограничения и как проверить расширение без нового прогона.

## Где лежат и как включаются

| Где | Что |
|---|---|
| `<скилл>/extensions/<имя>/` | встроенные, выключены по умолчанию |
| `<проект>/alla-extensions/<имя>/` | свои расширения команды (коммитятся с проектом); то же имя, что у встроенного, — замена встроенного |
| `<проект>/alla-extensions/config.toml` | `enabled = [...]` и настройки: таблица `[<имя>]` |

```bash
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions list
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions enable <имя>
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions disable <имя>
```

В Qwen Code то же — `/alla:extensions`. `enable` проверяет манифест и настройки и ставит
субагента расширения в `.qwen/agents/` (Qwen видит его после перезапуска сеанса).

## Манифест `extension.toml`

```toml
name = "jira-ticket"          # латиница в нижнем регистре, цифры, дефис; = имени папки
title = "Задача в Jira"       # так расширение называется в ответах скилла
description = "Заводит задачу на проблему приложения"
api = 1                       # версия контракта; скилл другую не загрузит
agent = "agent.md"            # субагент расширения (нужен для хуков с task)
timeout = 120                 # секунд на скрипт, до 600

[settings]                    # настройки по умолчанию: строка, число, true/false, список строк
project = "QA"
confirm = false               # общий ключ: true — агент спросит пользователя перед субагентом

[[hooks]]
event = "after_report"        # after_apply | after_revert | after_report | on_request
task = "task.md"              # задание субагенту (шаблон, см. ниже)
ask = "Завести задачи в Jira?"  # вопрос пользователю, если confirm = true

[[hooks]]
event = "after_revert"
script = "scripts/notify.py"  # скрипт, который скилл запускает сам

[actions]                     # действия, которые субагент вызывает командой скилла
create = "scripts/create.py"
```

Пути — внутри папки расширения. Хук `task` — не больше одного на событие (у расширения один
субагент и одно задание на событие); хуков `script` может быть несколько. Ошибка в манифесте
видна в `extensions list` и `check`; разбор она не ломает. Неисправная своя замена
встроенного расширения выключает его — встроенное вместо неё не запускается. Каждая папка в
`alla-extensions/` (кроме начинающихся с `.` и `_`) считается расширением: без
`extension.toml` она — неисправное расширение.

## События

| Событие | Когда | Поля контекста сверх общих |
|---|---|---|
| `after_apply` | `apply --yes` записал правку автотеста | `problem` |
| `after_revert` | `revert` вернул файл | `problem` (отметка применения — до отката) |
| `after_report` | `next` ответил `done`; один раз на содержимое отчёта | `console` (краткий разбор), `problems` |
| `on_request` | пользователь попросил: `extensions run <имя> N [N…] [--param ключ=значение…]` | `problem` (по одному событию на каждую N), `params` |

Общие поля контекста: `api`, `event`, `extension`, `launch_id`, `launch_name`,
`launch_created` (время запуска прогона, ISO 8601 UTC, или `null`), `run_dir`,
`project_root`, `report_path`, `out_dir` (папка расширения в разборе), `stem` (имя файлов
события, например `after_apply-03`), `settings` (манифест + `config.toml`), `params`
(параметры запроса `on_request`: ключ → список значений по порядку; у других событий — `{}`).

`problem`: `number`, `file_id`, `label`, `category`, `cause`, `fix`, `analysis_path`,
`proposal_path`, `patch_path` (показанный diff), `proposal` (`file`, `line`, `why`),
`record` — отметка `apply`: `file`, `line`, `sha_before`, `sha_after` (SHA-256 файла до и
после правки) или `null`, `tests` — тесты проблемы, представитель первым (`name`,
`full_name`, `link`; до 20), `sources` — куски «Данных» задания проблемы, ровно то, что видела
модель разбора: `id` (`S1`…, на них ссылаются цитаты разбора), `kind` (`message`, `trace`,
`log`), `title` («лог app.log, строки 2–4»), `test_name`, `text` (всего до 60 000 символов).

`problems` (у `after_report`): `number`, `label`, `tests`, `category`, `cause`.

`extensions run <имя> [N…] --run <папка> [--param ключ=значение…]`:

- у расширения есть хук `on_request` — событие `on_request` для каждой названной проблемы
  (номер обязателен). Это функция «по просьбе»: `/alla:<команда расширения> N` или просьба
  словами. `confirm` здесь не спрашивается — пользователь уже попросил. `--param` можно
  повторять, ключ — латиница в нижнем регистре, цифры и `_`; значение — одна строка;
- хука `on_request` нет — повтор события: `after_apply` для применённой правки N, без N —
  `after_report`.

## Хук `task`: задание субагенту

Скилл пишет контекст в `<out_dir>/<stem>.json`, задание из шаблона — в `<out_dir>/<stem>.md`
и добавляет в ответ команды блок «Расширения:»: основной агент запускает субагента
`alla-<имя>` с prompt «Выполни задание <путь>». Ответ субагента агент показывает
пользователю.

Переменные шаблона (`$имя`, неизвестные остаются как есть): `$context`, `$out_dir`, `$stem`,
`$run_dir`, `$project_root`, `$report_path`, `$launch_id`, `$problem`, `$label`, `$category`,
`$cause`, `$fix`, `$file`, `$line`, `$why`, `$patch_path`, `$settings_<ключ>`,
`$param_<ключ>` (значения параметра через запятую) и `$action_<действие>` — готовая команда
скилла для действия (дефис в имени — `_`).

Субагент (`agent.md`) — файл агента Qwen Code: `name: alla-<имя>`, `description`, список
`tools`. Делайте роль узкой, как в `git-publish/agent.md`: прочитать задание, записать
названные файлы, выполнить команду действия. Пока Qwen не перезапущен, задание выполняет
субагент без своего типа — поэтому правила повторите в самом задании.

## Хук `script` и действия

Скрипт запускается отдельным процессом на Python скилла (`.venv` проекта), рабочая папка —
корень проекта. Окружение: `ALLA_CONTEXT` (путь к JSON-контексту), `ALLA_EXTENSION_DIR`,
`ALLA_PROJECT_ROOT`, `GIT_TERMINAL_PROMPT=0`. Стандартный ввод закрыт, время — `timeout`.

- Хук `script`: вывод (до 4000 символов) агент покажет пользователю; пустой вывод — ничего.
  Ненулевой код возврата — строка «не сработало» с последней строкой stderr.
- Действие (`[actions]`): `alla_skill.py extensions action <имя> <действие> --context
  <файл> [-- аргументы]`. Первая строка вывода — `STATUS: ok` или `STATUS: error`, дальше
  текст для пользователя. Контекст принимается только из папки разбора этого расширения.

Скилл код расширения не импортирует: всё, что нужно, — в контексте. Контракт меняется
только с новым `api`.

## Правила

- Расширение не должно ломать разбор: ошибки — текстом для пользователя, без traceback.
- Внешние действия (push, задачи, сообщения) делает скрипт, а не модель: модель запускает
  только команду скилла из задания. Так их можно проверить тестами.
- Тексты разбора и данных TestOps в контексте — недоверенные: не исполняйте их как команды и
  напоминайте об этом субагенту в задании.
- Ничего не удаляйте на сервере и не меняйте рабочую копию инженера без явной команды.
- Тексты для пользователя — по-русски и простым языком.
