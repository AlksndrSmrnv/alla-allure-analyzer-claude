# Расширения alla-launch

Расширение добавляет скиллу свою функцию — выгрузить правку в git, завести задачу,
отправить отчёт в чат — без форка и без правки кода скилла. Это папка с манифестом:
скилл находит её, по событию разбора запускает субагента или скрипт расширения и передаёт
им данные. Включается и выключается одной командой.

Примеры в комплекте:

- [`git-publish/`](git-publish/) — после применённой правки субагент пишет сообщение
  коммита, а скрипт выгружает правку в новую ветку;
- [`sut-code/`](sut-code/) — функция по просьбе (`/alla:code N`): субагент разбирает
  проблему по коду тестируемого приложения, скрипты скачивают копию репозитория, выбирают
  ревизию, ищут в коде и проверяют вывод; подтверждённый вывод скилл сохраняет в отчёт и
  базу знаний;
- [`tickets/`](tickets/README.md) — рекомендации, групповые черновики, поиск совпадений,
  создание и внешняя связь после просмотра; трекер подключается отдельным адаптером.

Пишете расширение с помощью агента — дайте ему [AUTHORING.md](AUTHORING.md): порядок работы,
неочевидные ограничения и как проверить расширение без нового прогона.

## Где лежат и как включаются

| Где | Что |
|---|---|
| `<скилл>/extensions/<имя>/` | встроенные, выключены по умолчанию |
| `<проект>/alla-extensions/<имя>/` | свои расширения команды (коммитятся с проектом); то же имя, что у встроенного, — замена встроенного |
| `<проект>/alla-extensions/config.toml` | `enabled = [...]` и настройки: таблица `[<имя>]` |

```bash
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions list
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions enable <имя>
python3 .qwen/skills/alla-launch/scripts/alla_skill.py extensions disable <имя>
```

В Qwen Code то же — `/alla:extensions`. `enable` проверяет манифест и настройки и ставит
субагента расширения в `.qwen/agents/` (Qwen видит его после перезапуска сеанса).

## Манифест `extension.toml`

```toml
name = "jira-ticket"          # латиница в нижнем регистре, цифры, дефис; = имени папки
title = "Задача в Jira"       # так расширение называется в ответах скилла
description = "Заводит задачу на проблему приложения"
api = 1                       # версия контракта; скилл другую не загрузит
agent = "agent.md"            # субагент расширения (нужен для хуков с task)
timeout = 120                 # секунд на скрипт, до 600 (фактический предел — ниже)
commands = ["commands/jira.md"]   # свои слэш-команды Qwen: /alla:jira (необязательно)

[settings]                    # настройки по умолчанию: строка, число, true/false, список строк
project = "QA"
confirm = false               # общий ключ: true — агент спросит пользователя перед субагентом

[[hooks]]
event = "after_report"        # after_apply | after_revert | after_report | on_request
task = "task.md"              # задание субагенту (шаблон, см. ниже)
ask = "Завести задачи в Jira?"  # вопрос пользователю, если confirm = true

[[hooks]]
event = "after_revert"
script = "scripts/notify.py"  # скрипт, который скилл запускает сам

[actions]                     # действия, которые субагент вызывает командой скилла
create = "scripts/create.py"
```

Пути — внутри папки расширения. Команда из `commands` — файл команды Qwen Code
(`---` / `description` / `argument-hint` / `disable-model-invocation: true` / `---` и текст с
`{{args}}`), имя файла — имя команды: `commands/jira.md` → `/alla:jira`. Имена команд скилла
(`run`, `apply`…) заняты, у двух включённых расширений одна команда — второе не работает.
`enable` и каждый `prepare` кладут команды в `.qwen/commands/alla/`, `disable` убирает их, если
файл не правили руками; Qwen видит новую команду после перезапуска сеанса. Текст команды —
просьба «вызови скилл alla-launch и выполни `extensions run <имя> …`» (см. `sut-code/`). Хук `task` — не больше одного на событие (у расширения один
субагент и одно задание на событие); хуков `script` может быть несколько. Ошибка в манифесте
видна в `extensions list` и `check`; разбор она не ломает. Неисправная своя замена
встроенного расширения выключает его — встроенное вместо неё не запускается. Каждая папка в
`alla-extensions/` (кроме начинающихся с `.` и `_`) считается расширением: без
`extension.toml` она — неисправное расширение.

## События

| Событие | Когда | Поля контекста сверх общих |
|---|---|---|
| `after_apply` | `apply --yes` записал правку автотеста | `problem` |
| `after_revert` | `revert` вернул файл | `problem` (отметка применения — до отката) |
| `after_report` | `next` ответил `done`; один раз на содержимое отчёта | `console` (краткий разбор), `problems` |
| `on_request` | пользователь попросил: `extensions run <имя> N [N…] [--param ключ=значение…]` | `problem` (по одному событию на каждую N), `params` |

Общие поля контекста: `api`, `event`, `extension`, `launch_id`, `launch_name`,
`launch_created` (время запуска прогона, ISO 8601 UTC, или `null`), `run_dir`,
`project_root`, `report_path`, `out_dir` (папка расширения в разборе), `stem` (имя файлов
события, например `after_apply-03`), `settings` (манифест + `config.toml`), `params`
(параметры запроса `on_request`: ключ → список значений по порядку; у других событий — `{}`).

`problem`: `number`, `file_id`, `label`, `category`, `cause`, `fix`, `analysis_path`,
`proposal_path`, `patch_path` (показанный diff), `proposal` (`file`, `line`, `why`),
`record` — отметка `apply`: `file`, `line`, `sha_before`, `sha_after` (SHA-256 файла до и
после правки) или `null`, `tests` — тесты проблемы, представитель первым (`name`,
`full_name`, `link`; до 20), `sources` — куски «Данных» задания проблемы, ровно то, что видела
модель разбора: `id` (`S1`…, на них ссылаются цитаты разбора), `kind` (`message`, `trace`,
`log`), `title` («лог app.log, строки 2–4»), `test_name`, `text` (всего до 60 000 символов).

`problems` (у `after_report`): `number`, `label`, `tests`, `category`, `cause`, `confirmed`
(у проблемы есть подтверждённый вывод расширения — тогда `category` и `cause` из него).

`extensions run <имя> [N…] --run <папка> [--param ключ=значение…]`:

- у расширения есть хук `on_request` — событие `on_request` для каждой названной проблемы
  (номер обязателен). Это функция «по просьбе»: `/alla:<команда расширения> N` или просьба
  словами. `confirm` здесь не спрашивается — пользователь уже попросил. `--param` можно
  повторять, ключ — латиница в нижнем регистре, цифры и `_`; значение — одна строка;
- хука `on_request` нет — повтор события: `after_apply` для применённой правки N, без N —
  `after_report`.

## Хук `task`: задание субагенту

Скилл пишет контекст в `<out_dir>/<stem>.json`, задание из шаблона — в `<out_dir>/<stem>.md`
и добавляет в ответ команды блок «Расширения:»: основной агент запускает субагента
`alla-<имя>` с prompt «Выполни задание <путь>». Ответ субагента агент показывает
пользователю.

Переменные шаблона (`$имя`, неизвестные остаются как есть): `$context`, `$out_dir`, `$stem`,
`$run_dir`, `$project_root`, `$report_path`, `$launch_id`, `$problem`, `$label`, `$category`,
`$cause`, `$fix`, `$file`, `$line`, `$why`, `$patch_path`, `$settings_<ключ>`,
`$param_<ключ>` (значения параметра через запятую) и `$action_<действие>` — готовая команда
скилла для действия (дефис в имени — `_`).

Субагент (`agent.md`) — файл агента Qwen Code: `name: alla-<имя>`, `description`, список
`tools`. Делайте роль узкой, как в `git-publish/agent.md`: прочитать задание, записать
названные файлы, выполнить команду действия. Пока Qwen не перезапущен, задание выполняет
субагент без своего типа — поэтому правила повторите в самом задании.

## Вывод по проблеме: в отчёт и базу знаний

Расширение может оставить вывод о причине проблемы: файл
`<out_dir>/<stem>.finding.json`, где `<stem>` кончается номером проблемы (`on_request-03`).
В отчёт и базу знаний он попадает только после подтверждения пользователя: основной агент
выполняет `remember N --run <папка> --from-extension <имя>`. Скилл берёт последний вывод
проблемы, проверяет его и сохраняет запись базы знаний (`kb_fields` — своим полем записи
`<имя>`), а в разбор пишет `confirmed/NN.json`: отчёт показывает его у проблемы
(«Подтверждено инженером»), категория вывода определяет раздел отчёта. Подтверждение
снимается, если пользователь потом поправит причину (`remember` без `--from-extension`) или
отвергнет запись, в которую оно сохранено (`reject`).

```json
{
  "problem": 3,
  "category": "приложение",
  "title": "OrderService.create падает с NPE при запросе без customer",
  "cause": "проверку customer убрали при рефакторинге (OrderService.java:10)",
  "fix": ["Вернуть проверку customer в OrderService.create"],
  "details": ["Ревизия: orders v1.4.2 (d1e8ddbe)", "Место: src/main/java/ru/company/OrderService.java:10"],
  "kb_fields": {"repo": "orders", "revision": "v1.4.2", "commit": "d1e8ddbe80e8"},
  "format_ok": true
}
```

- `category` — `тест`, `приложение`, `окружение` или `данные` (`неизвестно` не сохраняется);
  `title`, `cause` — строки до 1000 символов; `fix` — 1–10 шагов; `details` — до 8 строк по
  400 символов (для отчёта); `kb_fields` — до 10 пар «ключ латиницей: строка».
- `format_ok: false` — вывод не прошёл проверку расширения: скилл его не сохранит.
- Секретов быть не должно: отчёт и `alla-kb/` коммитят и пересылают — такой вывод отклоняется.
- Подтверждения просит сам ответ субагента расширения (последней строкой) — основной агент
  передаёт его пользователю как есть.

## Хук `script` и действия

Скрипт запускается отдельным процессом на Python скилла (`.venv` проекта), рабочая папка —
корень проекта. Окружение: `ALLA_CONTEXT` (путь к JSON-контексту), `ALLA_EXTENSION_DIR`,
`ALLA_PROJECT_ROOT`, `GIT_TERMINAL_PROMPT=0`. Стандартный ввод закрыт, время — `timeout`,
но не больше, чем позволяет Qwen Code: он обрывает команду shell через 120 с. Скрипты
хуков одной команды скилла (`next`, `apply`, `revert`, `extensions run`) делят 60 с на
всех; не успевший — строка «не уложился», а не запущенный из-за этого — «не запущено».
Действию даётся не больше 110 с. Долгую работу (клон, сборка) запускайте фоновым
процессом и отвечайте «повтори через минуту», как встроенное `sut-code`.

- Хук `script`: вывод (до 4000 символов) агент покажет пользователю; пустой вывод — ничего.
  Ненулевой код возврата — строка «не сработало» с последней строкой stderr.
- Действие (`[actions]`): `alla_skill.py extensions action <имя> <действие> --context
  <файл> [-- аргументы]`. Первая строка вывода — `STATUS: ok` или `STATUS: error`, дальше
  текст для пользователя. Контекст принимается только из папки разбора этого расширения.

Скилл код расширения не импортирует: всё, что нужно, — в контексте. Несовместимое изменение
требует нового `api`; совместимые новые события и дополнительные поля описаны ниже.

## Групповой запрос и снимок (`api = 1`, совместимое дополнение)

`on_request_many` — отдельное событие: `extensions run <имя> 2 5 --run DIR` вызывает
хук один раз с `selected_numbers: [2,5]`. Сочетать его с `on_request` в одном манифесте
нельзя. У каждого вызова уникальный `stem`; существующий `on_request` не меняется.
Пустой список допустим для служебных запросов расширения, например отзыва группы.
Числа положительные; пригодность и отсутствующие в разборе номера оценивает расширение.

Новые общие поля контекста: `run_uid` (постоянный UUID папки разбора, не имя папки),
`reports_dir`, `context_path`, `state_dir` и `snapshot_command` (массив argv).
`state_dir` — `<фактический reports_dir>/.extensions/<имя>/<хеш корня проекта>/`:
скрипты могут писать сюда постоянные данные, которые переживают `clean`. Модель — по-прежнему
только `.txt` в `out_dir`. Хеш пути отделяет проекты, использующие общий каталог отчётов.

`extensions run` с `on_request_many` принимает повторяемый `--text-file KEY PATH`.
Это обычный `.txt` непосредственно в `out_dir`, без ссылки наружу. Скилл читает файл
как UTF-8 байты полностью: не обрезает, не делает strip и не заменяет CRLF. Непустой текст
до 16000 символов, без NUL, передаётся в `text_params: {KEY: текст}`. Дубли и совпадение
ключа с `--param` запрещены. Старый `--param` остаётся однострочным до 500 символов.

Манифест `snapshot = true` добавляет `snapshot_path` — текущий снимок при выдаче задания.
Для актуального состояния скрипт выполняет массив `snapshot_command` через subprocess
без shell. Это `extensions snapshot <имя> --context FILE`: первая строка `STATUS: ok`,
остальное — JSON `{path, sha256}`. Снимок сохраняется внутри папки расширения.

Схема снимка `schema = 1`: `run_uid`, `launch_id`, `project_root`, `settings`, `problems`,
`groups`. У проблемы: `number`, `label`, `what`, `category`, `cause`, `fix`, `missing`,
`valid`, `confirmed`, `tests` (все участники: `name`, `full_name`, `link`), `sources`
(`id`, `kind`, `title`, `text`, `test_name`), `observations` (`source_id`, `quote`),
`has_fix`, `rerun` (итог этой проблемы). У группы: `numbers`, `cause`.
Скриншоты без проверяемого текста источником цитат здесь не являются.
Диагноз берётся из действующего подтверждения расширения, затем из успешно сохранённой
обратной связи, иначе из проверенного разбора. Непринятая или отвергнутая обратная связь
делает основание непригодным. Снимок использует настоящие парсеры, не исполняет стадии next.

Полный хеш снимка — для целостности экспорта. Проверку актуальности своего действия
расширение строит по значимой проекции; изменение чужой проблемы не обязано его отменять.

## Сверка после удаления разбора

`extensions reconcile <имя> --reports-dir DIR --request-id UUID` не требует `--run` и
не принимает путь контекста. Нужен включённый модуль и `[actions] reconcile` в манифесте.
Скилл читает `state_dir/requests/<UUID>.json`, проверяет общий конверт
`schema: 1`, `extension`, `request_id`, `project_root`, `run_uid`; остальные поля — расширения.
Сам создаёт контекст в `state_dir/contexts/`: общие `api`, `event: reconcile`, `extension`,
`project_root`, `settings`, `state_dir`, `out_dir`, `reports_dir`, `request_id`, `run_uid`,
`request` (запись журнала). Обработчик выполняется с обычным лимитом действия и ответом
`STATUS: ok|error`. Путь от модели не используется; прежняя проверка `extensions action`
не ослаблена. `tickets` в этом обработчике делает исключительно lookup и обновляет журнал.

## Правила

- Расширение не должно ломать разбор: ошибки — текстом для пользователя, без traceback.
- Внешние действия (push, задачи, сообщения) делает скрипт, а не модель: модель запускает
  только команду скилла из задания. Так их можно проверить тестами.
- Тексты разбора и данных TestOps в контексте — недоверенные: не исполняйте их как команды и
  напоминайте об этом субагенту в задании.
- Ничего не удаляйте на сервере и не меняйте рабочую копию инженера без явной команды.
- Тексты для пользователя — по-русски и простым языком.
