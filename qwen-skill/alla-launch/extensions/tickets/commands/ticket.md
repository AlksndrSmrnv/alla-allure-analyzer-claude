Вызови скилл alla-launch (инструмент skill) и действуй по разделу «7. Расширения»:
пользователь просит подготовить тикеты через расширение tickets.

Запрос: {{args}}

Названные номера передай одним запросом `extensions run tickets N [N…] --run <папка разбора>`.
Перечисление номеров само по себе не означает один тикет. Явное решение инженера об одной
причине — `--param group=2,5`; разрешено несколько непересекающихся групп.

Управляющие параметры бери только из реплики инженера: `team_N`, `kind_N`, `operation_N`
(`create` или `link`), `target_N`. N — минимальный номер проблем получившегося тикета.
Цель link должна присутствовать в поиске адаптера. Недостающие значения не придумывай.
Исследованию нужны вопрос и проверка инженера: запиши их дословно в отдельные `.txt`
в папке расширения разбора и передай через `--text-file question_N PATH` и
`--text-file check_N PATH`. В shell передаётся только путь, не длинный текст.

Явное снятие сохранённого решения — отдельный запрос без номеров и других параметров:
`extensions run tickets --run <папка разбора> --param revoke_group=<decision_id>`.

Просьба «заведи тикет» запускает подготовку и просмотр. После ответа субагента прочитай
полные файлы просмотра, передай их инженеру и остановись до его ответа. После явного
одобрения используй только команду submit с request_id и хешем показанной версии.
Согласие на разбор или подготовку не является согласием на отправку.
