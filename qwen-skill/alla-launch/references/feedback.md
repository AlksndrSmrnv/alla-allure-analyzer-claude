# Обратная связь: сохранить причину и рецепт в базу знаний проекта

Когда пользователь называет причину падения и/или рецепт (или поправляет твой разбор, или
подтверждает его), это сохраняется в базу знаний (`alla-kb/`) командами `remember` и `reject`.
Папку (корень проекта или модуль многомодульного проекта) выбирает скрипт по тестам проблемы
и называет в ответе. Короткая
версия и готовые команды с нужным `--run` есть в выводе `STATUS: done`.

**Папка разбора** — папка того отчёта, о котором говорит пользователь: там лежит его
`report.md` (строка «Полный отчёт: …/report.md»). Если в сессии было несколько разборов, не
путай их: во всех командах ниже `--run` — именно эта папка; готовые команды есть в выводе
`done` этого разбора.

## Порядок

1. Запиши `feedback/NN.md` в папке разбора (write_file) — формат ниже.
2. Выполни `python3 .qwen/skills/alla-launch/scripts/alla_skill.py remember N --run <папка разбора>`
   (команду с абсолютным путём бери из вывода `done`). Если в задании кластера была запись
   базы знаний и пользователь уточняет именно её — добавь `--entry <id>`. Если пользователь
   просто подтвердил твой разбор без правок («да, всё верно, запомни») — файл не пиши, а
   добавь `--from-analysis`: тогда берётся `analyses/NN.md`, он должен проходить проверку
   формата (`references/analysis-format.md`, в том числе цитаты наблюдений), а существующий
   `feedback/NN.md` игнорируется.
3. `STATUS: fix` — исправь `feedback/NN.md` по замечаниям и выполни команду из вывода.
   `STATUS: saved` — скажи, что рецепт сохранён, и напомни закоммитить папку, которую назвал
   скрипт (`alla-kb/` или `<модуль>/alla-kb/`).

Если пользователь говорит, что известная проблема из базы знаний к ошибке N не относится:
`... alla_skill.py reject N <id> --run <папка разбора>`.

## Шаблон `feedback/NN.md`

```text
НАЗВАНИЕ: <коротко, 3–8 слов>
ПРИЧИНА: <тест|приложение|окружение|данные> — <причина со слов пользователя>
КАК ИСПРАВИТЬ:
1. <шаг рецепта>
ПРИЗНАК: <1–3 строки дословно из сообщения об ошибке или лога>   (необязательно)
```

## Правила по полям

- Пиши **со слов пользователя**, не додумывай. Другие разделы разбора (`ЧТО СЛОМАЛОСЬ`,
  `НАБЛЮДЕНИЯ`, `НЕ ХВАТАЕТ`, `КОД`, `БАЗА ЗНАНИЙ`) в этом файле не нужны.
- **НАЗВАНИЕ** — 3–8 слов; длиннее 120 символов обрезается. Не указано — возьмётся из
  «ПРИЧИНА» этого файла.
- **ПРИЧИНА** — первым словом категория `тест`, `приложение`, `окружение` или `данные`
  (описание категорий — `references/analysis-format.md`). Категорию `неизвестно` запоминать
  нельзя.
- **КАК ИСПРАВИТЬ** — рецепт обязателен, нумерованные шаги.
- **ПРИЗНАК** — 1–3 строки, которые по ним скилл узнает проблему в следующих прогонах.
  Каждая строка должна дословно (без учёта чисел, ID, времени и пробелов) находиться в
  тексте ошибки, трейса или лога кластера из задания; скопируй её оттуда. Если признака нет,
  берётся собственный признак кластера; если и его нет, скрипт попросит добавить `ПРИЗНАК`.
  В `alla-kb/` признак хранится нормализованным: вместо UUID, дат, адресов почты, IP и чисел
  стоят метки `<ID>`, `<TS>`, `<EMAIL>`, `<IP>`, `<NUM>`.
- **Секреты** (пароли, токены, ключи, пароль в URL) в файл не пиши: скрипт такие строки
  отклонит, потому что `alla-kb/` коммитится.

## Пример

<!-- example: feedback-ok -->
```text
НАЗВАНИЕ: NPE в OrderService при пустом customer
ПРИЧИНА: приложение — сервис заказов не проверяет customer
КАК ИСПРАВИТЬ:
1. Передавать customer в запросе создания заказа
ПРИЗНАК: java.lang.NullPointerException: customer is null
```

## Что может ответить скрипт (`STATUS: fix`)

| Замечание | Что сделать |
|---|---|
| нет файла обратной связи | записать `feedback/NN.md` со слов пользователя; если он подтвердил разбор как есть — `--from-analysis` |
| разбор кластера не прошёл проверку формата (с `--from-analysis`) | `analyses/NN.md` не переписывай: спроси пользователя причину и рецепт и запиши `feedback/NN.md`, затем `remember` без `--from-analysis` |
| в «ПРИЧИНА:» первым словом нужна категория | поставить `тест`, `приложение`, `окружение` или `данные` |
| нет «КАК ИСПРАВИТЬ:» — рецепт обязателен | добавить шаги |
| нет признака ошибки | добавить `ПРИЗНАК` из текста ошибки или лога |
| строки признака нет в данных кластера | скопировать строку дословно из задания кластера |
| строка похожа на секрет | убрать секрет из текста |

Лимита попыток у `remember` нет, но повторять команду вслепую не нужно: сначала исправь файл.
Если файл соответствует этому справочнику, а скрипт его отклоняет, это неполадка скилла:
сообщи о ней (`references/problem-report.md`).
