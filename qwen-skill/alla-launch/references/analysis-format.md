# Формат разбора кластера: `analyses/NN.md`

Пишешь на шаге `STATUS: analyze` (и заново на `STATUS: fix`). Один файл на проблему, `NN` —
номер из задания, только через write_file. Названия разделов — как здесь, заглавными и
по-русски: другие («ВЫВОД», «ЧТО ПОШЛО НЕ ТАК») скрипт не распознаёт. Проверка идёт при каждом
`next` (в пакетах — `verify`); попытки и «формат нарушен» — в `protocol.md`.

## Шаблон

```text
ЧТО СЛОМАЛОСЬ: <что увидел тест, 1–2 предложения>
ПРИЧИНА: <тест|приложение|окружение|данные|неизвестно> — <предполагаемая причина>
НАБЛЮДЕНИЯ:
- [S<номер>] «<дословная цитата из этого куска данных>»
НЕ ХВАТАЕТ: <каких данных нет и какая проверка различит версии> | нет
СОГЛАСОВАННОСТЬ: одна причина | разные проблемы — <чем отличаются примеры> | недостаточно данных   (только если в данных несколько примеров)
КАК ИСПРАВИТЬ:
1. <шаг>
КОД: <путь от корня проекта>:<строка> — <что там>   (необязательно)
БАЗА ЗНАНИЙ: <id записи> | нет   (только если задание предлагало записи)
```

`(необязательно)`, `(только если …)` и остальные пометки в скобках в файл не пиши.

## Куски данных и их id

В разделе «Данные» задания каждый кусок идёт под заголовком `--- [S… · …] ---` со своим
id. Номера идут по порядку из тех кусков, что есть: обычно сообщение об ошибке, стек-трейс,
затем фрагменты лога с вложением, строками и тестом; нет сообщения — S1 уже трейс. Бери id
только из заголовка куска. Пример (на нём построены примеры ниже, если у примера не сказано
другое):

<!-- example-data -->
```text
--- [S1 · сообщение об ошибке · тест createOrder] ---
expected: <200> but was: <500>

--- [S2 · стек-трейс · тест createOrder] ---
java.lang.AssertionError: expected: <200> but was: <500>
	at ru.company.orders.OrderTest.createOrder(OrderTest.java:6)

--- [S3 · лог app.log · строки 2–4 · тест createOrder] ---
2026-09-01 10:00:01 [ERROR] OrderService: failed to create order
java.lang.NullPointerException: customer is null
	at ru.company.OrderService.create(OrderService.java:10)
```

Цитировать можно только куски с таким заголовком. Остальное в задании — «Шаг теста»,
«Корреляция запроса», «Кадры стека из кода проекта», «Строки стек-трейса без файлов»,
«База знаний проекта», список тестов, пометки отбора вроде `[… пропущено блоков: 2, строк:
7 …]` — не цитируй: этих строк нет ни в одном куске, и скрипт цитату не примет. Нужной
строки кадра нет в стек-трейсе (он обрезан) — значит, её нельзя процитировать.

## Что писать в каждом разделе

- **ЧТО СЛОМАЛОСЬ** — что не получилось у теста, 1–2 короткие фразы простым языком, как
  коллеге, который не видел лог. Стек-трейс не пересказывай. Лог без явных ошибок — прямо
  скажи об этом и строй вывод по ошибке, трейсу и коду. Если есть только INFO-лог без
  ошибки, нет симптома и подтверждённой причины в точной записи базы знаний — `неизвестно`;
  чего не хватает — в «НЕ ХВАТАЕТ», не здесь.
- **ПРИЧИНА** — первым словом ровно одна категория, дальше «—» и предполагаемая причина,
  одной фразой:

  | Категория | Когда |
  |---|---|
  | `тест` | дефект в коде автотеста: устаревший локатор, путь, ожидаемое значение, нет ожидания, неверная подготовка данных |
  | `приложение` | ошибка приложения: 5xx, исключение в логе приложения, неверный ответ; код 5xx без лога приложения — тоже `приложение`, а лог сервиса — в «НЕ ХВАТАЕТ» |
  | `окружение` | стенд, сеть, недоступный сервис, инфраструктура |
  | `данные` | тестовых данных нет или они не подходят |
  | `неизвестно` | ни одну из четырёх нельзя обосновать данными и кодом; чего не хватает — в «НЕ ХВАТАЕТ» |

  Слова «автотест», «стенд», «инфраструктура», «тестовые данные» скрипт принимает как
  синонимы, но пиши каноническое слово. Две категории сразу («приложение или
  окружение», «тест/данные») не принимаются: выбери одну.
- **НАБЛЮДЕНИЯ** — 1–3 строки `- [S3] «цитата»`, каждая — одной строкой файла: в скобках
  один id куска из «Данных» (без жирного, не `[S1, S3]`), в кавычках — строка, скопированная
  **из этого куска** дословно. Скрипт сверяет каждую цитату с данными: регистр, лишние
  пробелы и вид кавычек не важны, а слова — важны. Длинную строку сокращай многоточием «…»
  внутри неё: части между «…» должны идти в куске по порядку. Цитата — не короче 8 букв и
  цифр. Первой ставь строку, на которой держится причина; есть явная ошибка в логе — строку
  из лога. Причина взята из записи базы знаний — цитируй строку куска, совпавшую с её
  признаком. Пояснение после цитаты — через «—» (`- [S3] «…» — почему это важно`) или без
  него. Цитата показывает только, что строка есть в данных: причину, которой в данных нет,
  она не подтвердит. Без наблюдений — только при категории `неизвестно`: тогда строку
  `НАБЛЮДЕНИЯ:` не пиши совсем (не «нет» и не «-»).
- **НЕ ХВАТАЕТ** — каких данных нет, чтобы подтвердить причину, и какая проверка различит
  версии («нет лога auth-service за время теста — по нему видно, принимал ли сервис
  соединения»). Если всего хватает — `нет`. При категории `неизвестно` — обязательно по
  существу.
- **СОГЛАСОВАННОСТЬ** — только если в «Данных» несколько примеров (строка «Примеров в
  данных: …» и блоки «### Пример 1 — …»); иначе строку не пиши. Сравни примеры и напиши
  одно из трёх: `одна причина` — ошибки всех примеров сводятся к одной; `разные проблемы —
  <чем отличаются примеры>` — у примеров разные ошибки (например, в логах разные
  исключения), тогда ПРИЧИНУ пиши по первому (типичному) примеру; `недостаточно данных` —
  сравнить нечем. Наблюдения можно брать из любого примера — у каждого куска свой id.
- **КАК ИСПРАВИТЬ** — нумерованные шаги, каждый начинается с глагола и называет
  конкретное действие. Не начинай строку шага со слов «Код:» или «Причина:» без номера
  или маркера списка: скрипт примет её за новый раздел.
- **КОД** — только если ты открывал файл проекта и он подтвердил вывод: путь от корня
  проекта, двоеточие, номер строки, «—» и что там происходит. Скрипт проверяет, что файл
  есть, а строка лежит внутри файла (имя без пути принимается, если такой файл один).
  Пути с пробелами можно заключать в кавычки или обратные кавычки:
  `КОД: "src/My Tests/OrderTest.java":42 — проверка ответа`. Для пути, содержащего
  ` — `, ` – ` или ` - `, кавычки обязательны.
  Ставь строку после шагов (перед `БАЗА ЗНАНИЙ`, если она есть). Выдуманный путь
  отклоняется. Без строки `КОД` для категории «тест» правку автотеста не предложат.
- **БАЗА ЗНАНИЙ** — только если в задании есть раздел «База знаний проекта»: `id` записи,
  которая подтверждает причину (не номер `[1]`, а сам id), или `нет`. Если раздела в
  задании нет, строку не пиши.

Только то, что видно в данных задания и в коде проекта; не хватает данных — `неизвестно`.

Разбор папки, созданной прежней версией скилла, проверяется по прежнему формату — без
«НАБЛЮДЕНИЯ» и «НЕ ХВАТАЕТ»: в «Задании» такого кластера и в ответе `fix` шаблон без них, а
заголовков `--- [S… · …] ---` в данных нет. Пиши по шаблону из задания и ответа.
