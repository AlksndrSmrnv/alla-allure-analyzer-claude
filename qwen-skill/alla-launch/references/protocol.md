# Протокол скилла: статусы, лимиты, файлы

Справочник к `SKILL.md`. Здесь — полный список ответов скрипта и что делать в каждом,
лимиты и разграничение: какие файлы пишешь ты, какие скрипт, каких не трогаешь.

## Как читать ответ скрипта

- Первая строка stdout — `STATUS: <статус>`. Если инструмент показывает stderr вместе с
  выводом, перед ней могут идти строки прогресса и предупреждения — ищи строку `STATUS:`.
- У `setup` строка `STATUS` печатается **в конце**, после вывода pip.
- Код возврата 0 у всех статусов, кроме `error`.
- Команды из вывода скрипта выполняй как есть: в них абсолютные пути и нужный `--run`.
- `next` без аргументов продолжает последний разбор; вторая строка ответа называет прогон и
  папку — убедись, что это тот, с которым ты работаешь.

## Статусы

| `STATUS` | Что значит | Что делаешь |
|---|---|---|
| `setup_required` | окружение скилла не готово | выполни команду `setup` из вывода (1–3 минуты, не прерывай), затем повтори исходную команду |
| `ready` | `setup` или `check` завершились успешно | ничего |
| `analyze` | нужен разбор одного кластера | прочитай `clusters/NN.md`, запиши `analyses/NN.md` (`analysis-format.md`), выполни `next` |
| `analyze_batch` | кластеров без разбора много (от 10) | раздай пакеты `batches/N.md` субагентам, дождись всех, выполни `next` |
| `fix` | файл не прошёл проверку (разбор, предложение, решение по похожим проблемам или обратная связь — вывод называет какой) | исправь файл по замечаниям и выполни команду из строки «Затем выполни»: `next` для разбора, предложения и решения, повторный `remember …` для обратной связи, `verify` у субагента |
| `propose` | по разбору виноват автотест | запиши решение в `proposals/NN.md` (`proposal-format.md`; одно предложение — одна правка: один файл, один блок БЫЛО/СТАЛО), выполни `next`; файлы проекта не меняй |
| `relate` | все кластеры разобраны, среди них есть похожие | прочитай `relate_task.md`, запиши `related.md` (`related-format.md`): у каких проблем одна причина — в отчёте они станут одной проблемой; выполни `next`. Нет похожих — шага нет |
| `summary` | все кластеры разобраны | прочитай `summary_task.md`, запиши `summary.md` (`summary-format.md`), выполни `next` |
| `done` | отчёт готов | выведи текст между `===ОТЧЁТ===` и `===КОНЕЦ===` дословно; дальше — блок «После отчёта» вывода (правки, обратная связь) |
| `diff` | `apply` показал diff правки | покажи пользователю diff, причину и строки «Проверь:», спроси «применить?»; дальше только после явного «да» |
| `applied` | `apply --yes` записал правку | скажи пользователю, что правка применена; выполни блок «Расширения:», если он есть; предложи запустить тест, сам не запускай |
| `reverted` | `revert` вернул файл | скажи пользователю |
| `saved` | `remember`, `reject` или `skip` выполнены | скажи пользователю; после `remember`/`reject` напомни закоммитить папку базы знаний, названную в ответе |
| `ok` | `verify` принял разборы (только у субагента); `extensions …` выполнена | субагент заканчивает работу; у `extensions run` — выполни блок «Расширения:», у остальных `extensions` — покажи ответ |
| `reviewed` | `review` проверил законченный разбор (только по прямой просьбе пользователя) | выведи текст между `===ОТЧЁТ===` и `===КОНЕЦ===` дословно; разбор заново не начинай |
| `error` | ошибка | покажи текст пользователю и остановись; если текст называет готовую команду скилла (`remember … --entry`, `prepare`, `setup --python`), её выполнить можно; правку `.env`, TLS и других настроек делает только пользователь |

`clean` тоже печатает `STATUS: done`, но это не «отчёт готов»: ничего выводить не нужно.
`extensions list|enable|disable` отвечают `ok` (покажи ответ пользователю) или `error`.
`extensions run` отвечает `ok` с блоком «Расширения:» — выполни блок, а не показывай его.
У расширения с функцией по просьбе (`sut-code` — разбор по коду приложения) `extensions run
<имя> N [N…] --run DIR [--param ключ=значение…]` запускает её для названных проблем
(`SKILL.md`, раздел 7); параметры — только из слов пользователя.
`extensions action` вызывает только субагент расширения по своему заданию; основной агент её
не выполняет.

Ответы `applied`, `reverted`, `done` и `ok` от `extensions run` могут заканчиваться блоком
«Расширения:» — пункты включённых расширений проекта. Выполни их после основного действия
статуса (`SKILL.md`, «7. Расширения»): «запусти субагента …» — вызов `agent` ровно как
написано, его ответ покажи пользователю (без строк «Проблема скилла: …»); «покажи
пользователю» — текст пункта как есть. Работу расширения (git, push) сам не делай.
Вывод без `STATUS:` (traceback) — тоже показать пользователю и остановиться; это неполадка
скилла: запиши её в `skill-problems.md` (`problem-report.md`), пользователю о ней не пиши.

## Лимиты

| Что | Лимит | Что происходит на пределе |
|---|---|---|
| Попыток исправить один файл | 3 (`попытка N из 3`) | разбор: третья версия принимается как есть, в отчёте пометка «формат нарушен»; предложение правки отбрасывается с пометкой; решение по похожим проблемам отбрасывается — проблемы не объединяются, в отчёте замечание |
| Похожих проблем в задании `relate` | до 15 групп по 8 проблем | остальные не сравниваются |
| Один и тот же файл без изменений | 3 вызова `next` подряд = 1 попытка | перезапиши файл (write_file) до `next`, иначе попытки тратятся впустую |
| Предложений правок на разбор | 5 | остальные помечаются в отчёте «лимит» |
| Файлов проекта на один кластер | 3 (только чтение) | не открывай больше |
| Пакет субагента | 6 кластеров | пакетов за волну — до 4 (`--workers N`, 1–8) |
| Проверок пакета `verify` | 3 раза на кластер | оставь как есть и назови номер в ответе |
| Один кластер в пакете | не больше одного раза | что субагенты не записали, идёт обычным `analyze` |
| `remember` | 3 отказа подряд по одной проблеме (`Попытка N из 3`) | `STATUS: error`: покажи замечания пользователю и не повторяй, пока он не уточнит причину или рецепт; следующая попытка — снова с первой |

Пакеты для субагентов используются только если субагентов можно запускать. Если инструмента
нет или запуск не удался, выполни `next … --serial` из вывода (кластеры пойдут по одному) — это
штатный запасной путь, а не отступление от сценария. Свои циклы вместо него не пиши.

## Какие файлы чьи

| Файл (в папке разбора) | Кто пишет | Тебе |
|---|---|---|
| `analyses/NN.md` | ты (`STATUS: analyze`, `fix`) | писать через write_file |
| `proposals/NN.md` | ты (`STATUS: propose`, `fix`) | писать через write_file |
| `related.md` | ты (`STATUS: relate`, `fix`) | писать через write_file |
| `summary.md` | ты (`STATUS: summary`) | писать через write_file |
| `feedback/NN.md` | ты (по просьбе пользователя) | писать через write_file |
| `skill-problems.md` | ты (неполадка скилла, `problem-report.md`) | писать через write_file; пользователю не выводить |
| `extensions/<имя>/*.json`, `*.md` (контекст и задание расширения) | скрипт | задание читает субагент расширения; основной агент передаёт только путь из блока «Расширения:» |
| `extensions/<имя>/…`, названные в задании расширения | субагент расширения | писать через write_file только их |
| `extensions/<имя>/*.finding.json` (вывод расширения по проблеме) | скрипт расширения | не читать и не менять; подтверждённый пользователем — `remember N --from-extension <имя>` |
| `confirmed/NN.json` (подтверждённый вывод расширения) | скрипт (`remember --from-extension`) | не читать и не менять: его показывает отчёт |
| `.alla-sut/` в корне проекта (копия кода приложения, `sut-code`) | скрипты расширения | читает только субагент расширения в папках ревизий из своего задания; основной агент — нет |
| `clusters/NN.md`, `batches/N.md`, `relate_task.md`, `summary_task.md` | скрипт | только читать |
| `report.md` | скрипт | читать не нужно: в чат идёт краткий разбор из вывода `done`; менять нельзя |
| `run.json`, `state.json`, `evidence/`, `.last_run`, `history.jsonl` | скрипт | не читать и не менять |
| `proposals/NN.patch`, `.orig`, `.applied.json` | скрипт (`apply`, `revert`) | не менять |
| `alla-kb/*.json` (в корне или `<модуль>/alla-kb/`) | скрипт (`remember`, `reject`) | только этими командами |
| файлы автотестов проекта | скрипт (`apply --yes --diff …`, `revert`) | читать можно; менять — только этими командами после «да» пользователя |
| `SKILL.md`, `references/`, `scripts/`, `tests/`, `extensions/`, `requirements*.txt`, `.env.example` | — | только читать; нашёл ошибку — запиши (`problem-report.md`) |
| `alla-extensions/` проекта (`config.toml`, свои расширения) | пользователь; `enabled` — команды `extensions enable`/`disable` | не читать и не менять |
| `.env` скилла, `.venv/` проекта | пользователь, `setup` | не читать и не менять |
