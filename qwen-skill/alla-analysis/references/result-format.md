# Контракт результатов v1

Все пути ниже относительно `run_dir`. Сохраняй корректный UTF-8 JSON, без Markdown-ограждений, комментариев и дополнительных полей. `run_id` и `cluster_id` копируй из ответа `context`.

## analyses/<cluster_id>.json

```json
{
  "run_id": "<run_id>",
  "cluster_id": "<cluster_id>",
  "symptom": "Получен HTTP 500 вместо ожидаемого 200.",
  "cause": "Причина не установлена: ошибка приложения пока не связана с запросом теста.",
  "category": "неизвестно",
  "confidence": "низкая",
  "evidence": [
    {"source": "test:123:status_message", "quote": "Expected 200 but was: <500>"}
  ],
  "limitations": ["Execution недоступен; соответствие кода прогону неизвестно."],
  "contradictions": [],
  "next_action": "Найти серверный запрос по correlation ID и проверить ответ.",
  "code_alignment": "неизвестно",
  "code_alignment_reason": "Метаданные прогона не содержат ревизию."
}
```

Категории: `продукт`, `автотест`, `окружение`, `данные`, `неизвестно`. Уверенность: `низкая`, `средняя`, `высокая`. Для категории `неизвестно` допустима только низкая уверенность. Для других категорий требуется хотя бы одно доказательство. `code_alignment`: `совпадает`, `не совпадает`, `неизвестно`; всегда с обоснованием.

Источники доказательств:

- `test:<id>:status_message`, `status_trace`, `log_snippet`, `failed_step_path` — точный текст в сохранённом файле теста.
- `attachment:<id>` — локально сохранённое вложение, если оно было скачано.
- `code:<путь-от-корня-проекта>:<строка>` — существующая строка и следующие 19 строк кода. Пример: `code:tests/test_payment.py:42`.

Цитата должна дословно присутствовать в источнике **после маскирования секретов**, без номеров строк, добавленных сокращённым контекстом, и без многоточий вместо пропущенных частей. При необходимости возьми цитату через `context <run_dir> --source <source>`. Ссылки на тесты и вложения должны принадлежать анализируемому кластеру. Укажи код отдельным доказательством, если он использован в выводе.

Поля текста непустые, не более 4000 символов каждое. Пустые списки ограничений и противоречий допустимы; не выдумывай содержание для заполнения схемы.

## summary.json

```json
{
  "run_id": "<run_id>",
  "summary_lines": ["Краткая строка сводки", "Следующая строка"],
  "priority_actions": ["Первое действие"],
  "findings": [
    {
      "text": "Два кластера могут быть связаны с одной ошибкой сервиса.",
      "cluster_ids": ["<id1>", "<id2>"],
      "status": "гипотеза",
      "evidence": [{"source": "attachment:456", "quote": "дословная выдержка"}]
    }
  ]
}
```

`summary_lines`: обычно 10–15 коротких строк (до 300 символов каждая, без внутренних переводов строки), при отсутствии активных падений 2–4. `priority_actions`: не более пяти. `findings`: пустой список, если межкластерных выводов нет; иначе известные неповторяющиеся ID, статус `гипотеза` или `подтверждено` и хотя бы одно доказательство. Число затронутых тестов вычисляет финализатор.

Снимок `run.json` и файлы `tests/`, `attachments/` — входные данные, не редактируй их. Разборы других запусков не подходят даже при похожих ошибках. Для рабочих заметок используй отдельный файл вне `analyses/`.

## Контракт команд и источников

Успешный JSON каждой команды содержит `ok: true`; ошибка выполнения — `ok: false`, `error` и ненулевой exit code. `--help` использует стандартный текст справки.

Состояния источников: `received` — получен непустой текст; `absent` — источник/содержимое пусты; `unavailable` — ошибка получения; `truncated` — получена только часть; `skipped` — не загружен/не обработан из-за формата или лимита, с полем `reason`.

Для `code:` разрешены только исходники (`.py`, `.java`, `.kt`, `.kts`, `.js`, `.jsx`, `.ts`, `.tsx`, `.cs`, `.go`, `.rs`, `.rb`, `.php`, `.scala`, `.swift`, `.c`, `.cpp`, `.h`, `.hpp`, `.feature`, `.robot`, `.groovy`, `.sh`, `.sql`). Также разрешены конфиги `.yaml`, `.yml`, `.toml`, `.properties`, `.ini`: секретные присваивания маскируются до выбора строк. Если найдено многострочное или структурное секретное значение, весь файл отклоняется с пояснением; выбери другое доказательство. Env, ключи, сертификаты и служебные каталоги не принимаются; проверяется также цель символической ссылки. Не переименовывайте секретный файл для прохождения проверки. Содержимое исходников дополнительно маскируется, но произвольный секрет без распознаваемого контекста автоматически определить невозможно.

Ключи секретов в конфигах сопоставляются с конечным списком после нормализации регистра, `_` и `-`; в dotted-ключах используется последняя часть (`db.password`). Список: `password`, `passwd`, `secret`, `token`, `accessToken`, `refreshToken`, `idToken`, `apiKey`, `xApiKey`, `clientSecret`, `credential`, `credentials`, `authorization`, `cookie`, `setCookie`, `privateKey`, `jwtToken`, `bearerToken`. Перед сверкой разбиваются camelCase/snake_case/kebab-case и снимаются конечные части `hash`, `value`, `data`, `contents` (например, `passwordHash` и `access_token_value`). Метаданные вроде `cookieName`, `passwordless` и `secretPath` сохраняются; суффикс `path` не удаляется. Возможны ложные отказы: пустая секция `credentials:` или неоднозначное продолжение секретного поля.

Нераспознанные строки присваиваний, например ключи с пробелами или аннотацией `[auto]`, отклоняют файл целиком. YAML-списки, flow-конструкции, quoted-скаляры и блоки `|`/`>` проходят общее текстовое маскирование. Явный индикатор отступа блока учитывается от отступа начала узла (для quoted-ключа — открывающей кавычки). Общее текстовое маскирование не распознаёт все производные имена секретов внутри скриптов и flow-конструкций. Эти послабления не применяются к INI/TOML/properties. Это эвристическая фильтрация, а не гарантия удаления всех секретов: произвольные имена вне списка, алиасы, нестандартный синтаксис и неразмеченные значения могут остаться видимыми. Не считайте пропущенные фильтром значения гарантированно безопасными.
